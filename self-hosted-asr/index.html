饭耳「自建服务」转写接口说明

饭耳按 OpenAI 的语音转文字接口 POST /v1/audio/transcriptions 对接你自己的转写服务。服务端用什么软件、什么模型都行，请求和返回按下面来就能接。

饭耳发什么

  • 地址：设置里填到 /v1 为止，比如 https://asr.example.com/v1，饭耳在后面接 /audio/transcriptions。https 和 http 都收（http 不加密，公网上能用 https 就用 https）；https 要正规证书，不收自签名证书。
  • 一块录音（通常 15 分钟）发一次 POST，multipart/form-data。每次都带请求头 Prefer: respond-async：服务支持异步就先回任务号、饭耳过一会再来查（见「异步」，推荐）；不认这个头、照旧同步回结果的，饭耳等着，最多等 600 秒。没有流式。「测试连接」测出只回文字的服务不整块发，切成小段一段发一次（见「只回文字的服务」）。
  • 填了密钥才带 Authorization: Bearer <密钥>（交任务和查任务都带）；没填就不带。
  • 整块送时一次就是一整块：通常 900 秒（15 分钟，切块结束可能多出零点几秒）的录音，文件约 7MB（约 7,000,000 字节）（AAC 单声道，实测平均每小时 29MB）。服务、反向代理的单次时长和上传体积上限都要放得下，体积建议留到 15MB 以上。收不下就回 HTTP 413，正文用错误体写清上限（如 {"error":{"message":"audio longer than 300 seconds","code":"audio_too_long"}}）；饭耳把它显示成「你的服务拒收了这段录音」，带上状态码和原话，不会自己改小再送。
表单字段 值
file 文件名 audio.m4a，Content-Type: audio/mp4（AAC 单声道；默认原样，15 分钟约 7MB，不压缩）
model 设置里填的模型名
response_format 「分说话人」关：verbose_json；开：diarized_json；只回文字的服务切小段送时用测试连接测出的那种（一般是 json）
temperature 0
chunking_strategy 只在整块送 diarized_json 时发，值 auto（OpenAI 的分人模型超过 30 秒必须带）；切小段送不发

不发 language、prompt、timestamp_granularities、stream。服务不认识的字段请忽略，不要报错（OpenAI 也是忽略的，2026-10-18 实测）。

饭耳要什么返回

HTTP 200，一个 JSON 对象。饭耳只读下表几样；task、language、duration、usage、id、type、words 等有没有都行。

字段 要求
segments 有就整块送：数组，一句一项；没人说话回 []。没有就按只回文字的服务切小段送（见下）
segments[].start、segments[].end 有 segments 时必须有，数字，单位秒，从这块录音开头算；0 ≤ start ≤ end ≤ 14400
segments[].text 有 segments 时必须有，字符串
segments[].speaker 可选；字符串（"A"、"SPEAKER_00"、"S01"）或整数（0、1）都行；没有就按不分说话人显示
text 只回文字的服务必须有（整段文字）；有 segments 时只用来分清「没人说话」和「有字没有每句时间」
  • verbose_json 和 diarized_json 按同一张表读：开着「分说话人」时回带 speaker 的 verbose_json 也行；关着时服务自己带了 speaker 也照样用。
  • 说话人标签只在这一块里有效：饭耳按出现顺序编成第 1、2、3 个人；跨块是不是同一个人由饭耳自己的声纹判断，服务不用管，也不用跨块保持一致。
  • 分段没有长度和条数限制，按时间先后排。建议一句一段（几秒到二三十秒）：饭耳里点一句话会从那句开头播放，一整块只回一段也能转，但只能从头播放。
  • 某一句的 start、end 缺了或超出范围，这一块整块算失败，不会只丢那一句。

异步（推荐，跑得慢的模型必用）

一块 15 分钟的录音，CPU 或小显卡上的模型常要转好几分钟，同步等容易超时（反向代理、隧道、手机切网都会断）。支持异步的服务交上就回，饭耳过一会再来查，连接不用一直开着；App 被挂起、断网，回来凭任务号接着查，不重交。

交任务：饭耳的 POST {地址}/audio/transcriptions 带 Prefer: respond-async，表单和同步一样。服务回：

  • HTTP 202，JSON {"id": "任务号", "status": "queued"}（status 也可以是 processing）。任务号是字符串，只用字母、数字和 -._~ 最稳。
  • 可以带 Location 响应头指明查询地址（相对路径或同一个服务的完整网址；放在反向代理的子路径后面时要写对前缀，不确定就别带）。Location 必须与提交地址的协议、主机、端口相同；指向其他服务的会报错，不会把密钥带到别处。

查任务：GET {地址}/audio/transcriptions/{id}（有 Location 用 Location），带同样的 Authorization。交上即可查询；未完成时从约 3 秒间隔起退避，最长 30 秒一次；一块最多查 24 小时。服务回 HTTP 200 和下面之一：

回包 意思
{"id":"…","status":"queued"} 或 "processing" 还在排队或在转，过一会再查（回 HTTP 202 也算还在转）
{"id":"…","status":"completed", …} 转完了：其余字段和同步的返回一样（segments、text，见「饭耳要什么返回」）
{"id":"…","status":"failed","error":{"message":"…","code":"…"}} 转失败了：饭耳把 code 和 message 放进出错详情；点重试会重新交
  • 只认这四个 status，别的值饭耳报「任务状态不认识」，不会一直等。
  • 找不到这个任务回 HTTP 404：饭耳重交一次；重交的也找不到就报失败，不再交（重交会让服务重算一遍）。
  • 任务状态和结果至少保留 24 小时；即使已经被查询到也不要立即删除：手机刚收到结果时可能被挂起，恢复后仍需查询。处理完即可删除临时录音，结果按保留期限清理。
  • 没带 Prefer: respond-async 的请求照旧同步回结果（老版本饭耳这样发）。
  • 只回文字的服务切小段送时，每段也照这个流程交和查。
  • 「测试连接」也走异步：交上测试音以后在设置页查到完成：测试音约 6 秒，每次请求最多等 30 秒，异步查询最多等 60 秒；没转完会提示，不会一直等 600 秒。

密钥校验、结果按 24 小时清理、同一时间只跑一个任务（显存不够时）请按自己的情况加。

只回文字的服务

只回整段文字、没有每句时间的服务也能接：返回里没有 segments、或 segments 空着却有 text，或者不认 verbose_json、diarized_json 但认 json。

  • 在设置里点「测试连接」时饭耳测出来并记住；换了地址、模型或「分说话人」开关，会重新测。
  • 以后每块：用手机自带的声音识别找出哪里有人说话，在停顿处切成最长约 30 秒的小段，没人说话的部分不发；每段发一次，response_format 用测出来的那种（一般是 json），不带 chunking_strategy。
  • 返回只要顶层的 text（字符串）。饭耳按句末标点（。！？!?）分句、按字数估每句的时间（点一句播放会差一两秒），说话的人由手机按声音认。
  • 一块要发二三十到四十次请求（15 分钟），服务要撑得住连着来的请求；支持异步的每段也是交了再查。

出错时

  • 回非 200 的状态码，最好带 OpenAI 格式的错误体 {"error":{"message":"…","type":"…","code":"…"}}，饭耳把 code 和 message 放进出错详情。
  • 不认要的 response_format 时回 400 或 422，正文里写出 response_format 或格式名：饭耳会提示「关掉/打开『分说话人』再试」。
  • 其他 4xx（录音太长、太大、你自己定的限制等）：饭耳提示「你的服务拒收了这段录音」，卡片上带状态码和你的错误码、原话，详情可以整段交给帮你搭服务的 AI；这不算饭耳出错。没有自定义错误码的 401、403 仍按密钥不对提示。
  • 没测过就只回整段文字（没有 segments，或 segments 空着却有 text）：饭耳提示「这个服务只回文字，没有每句时间」，点「测试连接」重测后改切小段送；这块不会当成没人说话。
  • 「测试连接」发一句约 6 秒的合成语音（m4a，不是录音）：回了带时间的 segments 就整块送；回了文字没有每句时间、或 400/422 不认这个格式，再用 response_format=json 发一次，回了文字就记成只回文字；最后不带密钥发一次，也回 200 会提示「服务没设密码」。
